# Consignes Codex — Code secret en couleurs

- Avant toute modification, lire `README.md` et les spécifications officielles disponibles : descriptif du projet édition 2.1 et contrat d'API commun 0.2, qui font autorité. Si un modèle officiel est fourni, vérifier les consignes associées avant de l'intégrer au projet.
- Signaler les spécifications manquantes, les contradictions et les ambiguïtés ; ne pas inventer de règles ni présenter un document absent comme disponible.
- Faire des changements petits et faciles à relire, limités à la demande. Préserver les fichiers utiles et les modifications existantes.
- Définir le résultat attendu avant chaque test, notamment pour le décompte des couleurs répétées et les propositions invalides.
- Après les changements, tester le comportement affecté et un cas valide pertinent. Pour une modification documentaire, vérifier le contenu et le diff ; si un test du jeu est impossible, le signaler.
- Rapporter les résultats réellement observés et identifier explicitement les comportements non vérifiés. Distinguer les résultats attendus du README des tests effectivement exécutés.
- Ne jamais inventer de résultats de tests, de preuves ou d'historique Git.
- Ne publier aucun fichier ni aucune modification, et ne supprimer aucun fichier, sans l'accord de l'utilisateur.
